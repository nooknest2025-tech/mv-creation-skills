# mv-qa

**モデルの目安: 標準モデル＋推論 medium**（迷ったら mv-direct で方針→ mv-run で実行）

## 自動 QA（mv 実行のたびに `<曲名>_vN_QA.md`）
互換MP4（H.264/yuv420p）/ faststart / 尺が曲と一致 / 音声コピー時のmd5（WAV等のAAC変換時は別項目）/ エンディングに文字が残らない / Drive 用 <100MB。❌ があれば理由と対処が日本語で出る。AAC変換時の合格を、元音声とのビット一致と説明しない。

## 人の目で（QA.md の後半にもある）
1. 冒頭3秒で掴めるか 2. サビ頭でカットと文字が音に合うか 3. 歌詞の誤字・読みにくさ 4. 顔や UI に文字が被っていないか 5. 同じ画の使い回しが目立たないか 6. 終わり方（ループ/余韻）
フレームを確認するなら `ffmpeg -ss 30 -i out.mp4 -frames:v 1 check.jpg` で数枚切り出して見る。
静止画は構図の確認に使い、同期・動きは音付き再生で別途確認する。全体表示を指定した画像は、動きや切り替えの途中も端が切れないかを見る。

## 生成MV・編集環境の追加確認

- 全シーンで本人・服・背景・ヘッドホン・マイク・ポップガード・配線の連続性を確認する。参照画像やプロンプトに書いたことを出力で守れた証拠にしない。
- 口同期は冒頭・中盤・末尾と問題の語を音付きで確認し、強い歌唱の中の表情、自然な瞬き、頭/手の動きも確認する。音声ストリームがあるだけで「聞いて確認した」としない。
- フレーム飛ばし、速度調整、静止延長、補間を行った箇所は、カクつき・口元の変形・不自然な停止を再確認する。
- 編集環境の納品では [実機テスト](../mv-workflow/references/review-and-studio.md) を行う。マウス操作・保存・プロセス再起動・変更保持・修正入りMP4出力を確認し、実装だけで完了にしない。既存CLI/リリックの回帰チェックも行う。

## 完成判定

確認ページで直接編集できると案内する場合、[確認ページの編集手順](../mv-workflow/references/review-and-studio.md) に従い、変更の即時プレビュー、正本への保存、プロセス再起動後の保持、修正入りMP4の出力を実際のMVで確認する。数値入力・メモ保存・JSONダウンロードの成功だけでは編集機能の合格にしない。未接続なら修正依頼用として明記し、動画自体のQAと分けて報告する。

音声を添付して生成した動画は、ショットの生成秒数・添付音声の実測秒数・実曲内の開始位置の記録を確認する。生成後の尺と、元曲を速度1倍で合わせた冒頭・中盤・末尾の同期も確認する。尺が同じだけで同期合格にしない。未聴取なら未確認として残す。

[mv-workflow](../mv-workflow/SKILL.md) に沿い、`production-review.md` の構成合意・素材採用・リリック方針・同期確認・技術QA・見た目の確認を読む。未確認や問題が残れば確認用初稿として渡し、残りを明記する。自動QAの全項目合格だけで完成版としない。承認ロックはユーザーがその版を承認した場合に `npm run approve -- N` で行い、エージェントのQA合格をユーザー承認の代わりにしない。

## パック内での実行

このファイルは配布用コピー。編集原本は管理用ワークスペースの `.agents/skills/`。制作時は、この配布パックのルートにある `AGENTS.md` を読み、コマンドは `remotion/` で実行する。本文の `input/`、`projects/`、`docs/`、`gen/` はパックのルートを基準に解決する。
