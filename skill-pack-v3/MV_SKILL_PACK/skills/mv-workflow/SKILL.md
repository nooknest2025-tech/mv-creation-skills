# MV制作の入口

このスキルは、この制作パックを使うときの全体進行を担当する。`start.bat` を使う場合も、直接コマンドを実行する場合も、同じ選択と確認を行う。コマンドの既定値や素材の見た目を、ユーザーの希望として扱わない。

## 最初の選択

音源・歌詞・画像・動画・キャラ素材を確認し、既に回答された内容は引き継ぐ。「開始」「MV作って」では、`npm run start` と同じ順で**1問ずつ**聞く（まとめて聞かない。毎回おすすめを先に示し、そのままでよければ OK で進む）。質問と選択肢の正本は `src/lib/startFlow.ts`。

- Q1 何がありますか？：曲と歌詞だけ（SRT/LRC/JSON等の歌詞データもOK）／＋画像／＋動画素材／＋キャラ素材（立ち絵・パーツ）。見つかった素材を先に伝えて選んでおく（`detectQ1`）。無い素材を選ばれたら置き場所を案内し、見つかった素材で続ける（`checkQ1`）。
- Q2 映像はどうする？：Q1 に合うものだけ（`q2Options`）。文字と図形だけ（文字PV。`--text-only`）／画像だけで作る／画像を動画にする（全部 or 選んだシーンだけ）／動画も入れる／画像を作る（無料：Grokアプリ等で手作業。続けて「作った画像を動画にもする？」）／立ち絵で作る。選択肢に金額は出さない（全部無料が基本）。曲と歌詞だけなら文字PV をすすめる。
- 無料の道（画像も動画も）: シーンごとのプロンプトと添付（キャラ参照／スタイル参照／背景参照／開始画（first frame）／終了画、ファイルの場所つき）を画面とファイルで渡す → ユーザーが好きなアプリで作って `input/made/` に入れる → 「作ったの入れた」で `npm run made`（名前は自由・混在OK・作り直しまで自動）。有料は MCP・生成APIにつなぐときだけ。呼ぶ直前に毎回プロンプト・添付（書き換え・スキップ可）・見積もりを見せて確認する。
- Q3 ここから先は？：おまかせ（既定。追加の質問なし）／半自動（`semiQuestions({ ..., flow: { q2, m } })` で Q1・Q2 に合う質問だけ: 見せ方・ジャンル・シーンの細かさ・リリックの雰囲気と書体、画像を作るときだけテイスト、画像があるときだけ動画化、キャラ素材があるときだけキャラの動き）／こだわり（見せ方は `allowedModes`、ジャンルは `allowedPresets`、画像なしなら構成は `TEXT_STRUCTURES`。歌詞の動きの変化は「標準」がおすすめ）。画像がないのに画像前提の構成やアニメ画像の生成を既定にしない。
- 画面：16:9／9:16／1:1／4:5／複数。最後に確認（素材・作り方と理由・費用・できあがり。`confirmLines`）を見せ、OK で作る。どの道でも編集画面用のプロジェクト（`out/editor-input.json`。文字PVは単色SVG背景）ができる。
- 自然文（「立ち絵＋タイポグラフィで」「ボカロっぽく」など）と旧フラグ（`--preset`・`--say`・`--aspect`）はそのまま使える。
- 見せ方は**複数選んで組み合わせ可**: 物語／リップシンク／ダンス／ライブ／リリックモーション／タイポグラフィ／モーショングラフィックス／立ち絵モーション（`tachie`。キャラ素材が必要。どの見せ方とも組み合わせ可）。例「ダンス＋リリックモーションで」「物語＋タイポグラフィで」「リップシンク＋モーショングラフィックスで」。セクションごとの配分と理由が自動で付く（例: サビは全画面タイポ）。`mv.config.json` では `combo: ["dance","lyric_motion"]`。「立ち絵で」「立ち絵＋タイポグラフィで」なら `combo` に `tachie` が入り、`npm run mv` は立ち絵ステージと編集画面用のプロジェクトを作って編集画面へ案内する（MP4 は編集画面から書き出す）。キャラ素材（`input/parts/`・`input/tachie/`）があると Q1 は「＋キャラ素材」、Q2 は「立ち絵で作る」がおすすめになる。

「この素材で作りたい」は、作り方までおまかせした回答ではない。おまかせが選ばれた場合は、選定理由を示して演出判断を進め、項目ごとの質問は増やさない。

## 演出案を具体化する

`mv-intake-analysis` と `mv-concept-storyboard` を使い、曲の長さ、歌詞のテーマ、素材の特徴から案をまとめる。少なくとも次をユーザーに見せる。

1. 全体の狙いと、曲に合う見せ場を2〜3個。
2. 秒数区間ごとの構成表：歌詞・セクション、使うキャラクターや素材、画面・動き、文字演出。自動カット一覧だけを構成提案の代わりにしない。
3. 素材の動かし方：静止画のカメラ移動、パーツアニメーション、生成動画などから適した方法を提案する。実際に行う方法を明記し、カメラ移動だけの静止画を演奏・ダンス・生成動画と説明しない。有料生成は `mv-video-generation` に従い見積もりと承認後に実行する。
4. `mv-lyric-motion` に従い、実際の歌詞を例に、書体・色・出入り・強調語の提案を示す。既存プリセットの設定名だけでは済ませない。

ユーザーが方向性を判断できる案と、代表的な画面や短い動きのプレビューを提示する。方向性の確認はまとめて行い、回答済みの希望や明示された裁量は尊重する。自動生成・自動同期の結果は、確認が済むまでは初稿として扱う。

## 冒頭のフック（どのMVでも必須）

- 最初の3秒で必ず視聴者を引き込む。ゆっくりのフェードイン、真っ暗や空白の画面、長いタイトル表示、何も起きない静かなイントロから始めない。
- 0〜3秒には、一番強い絵（キャラのアップや一番印象的な画像）と、ビートに合わせたカットやモンタージュを置く。できればサビやフックの一節を、歌詞を大きくはっきり見せてチラ見せする。
- 曲のイントロが長くても、0〜3秒は動きとメインの絵で埋める。イントロの前にサビのチラ見せから始めることも考える。
- 構成表の0〜3秒の行に、何を映すか（ショット・カット点・文字）を必ず書いて合意を取る。
- 本番を書き出す前に、0秒・1秒・2秒・3秒の静止画でプレビューを確認し、最初の3秒に何が映るかを依頼者に伝える（手順は [mv-qa](../mv-qa/SKILL.md)）。
- 理由：YouTubeでは、早く離脱される動画はおすすめされにくくなる。

## 生成サービス・MCPの確認

素材の動かし方を提案する前に、現在利用可能なツールを名前・説明から調べる。動画生成、画像生成、編集など、構成に役立つ能力を確認する。スキルにサービス名があるだけで接続済みと判断しない。候補のツール仕様を読み、参照画像の入力、秒数・縦横比、見積もり、生成状況の取得、結果の取得が可能かを確認する。接続確認のために生成ジョブを発行しない。

利用可能な方法と、この曲のどのショットで使うとよいかを演出案に含める。MCPがなくても、静止画、パーツアニメーション、ユーザーの手動生成動画の取り込みなどで進められる案を示す。適したMCPがある場合はそのツールを優先し、未接続の場合は未接続と説明する。MCPを使うこと自体を目的にしない。

生成動画を採用する場合は [mv-video-generation](../mv-video-generation/SKILL.md) を読み、次の工程をつなぐ。

1. ショットID、参照画像、動き、秒数、画面比率、モデル、テイク数を含む生成計画を作る。
   - 音声を添付する場合は `mv-video-generation` の音声区間ルールに従い、生成秒数と同じ長さの実曲区間を切り出す。速度を変えずに実測尺を照合し、検証した区間ファイルを添付する。全曲を添付してツールの尺調整に任せない。
2. 利用するサービスの見積もりツールや現在の料金情報で、合計金額またはクレジットを提示する。クレジットを根拠なく円やドルに換算しない。見積もれない場合は不明と伝え、費用が不明なまま生成しない。
3. 料金・クレジットと対象ショットの承認を確認して生成する。既に承認された範囲は引き継ぎ、追加テイク・再生成は予算範囲を確認する。
4. ジョブIDを保存して完了状況を取得し、成功した動画を取り込む。待機中や失敗したジョブを完成と扱わず、同じジョブを重複発行しない。
5. テイクをプレビューして比較し、採用する素材をタイムラインへ反映する。参照画像との一致、動き、意図しない変形や切れ、尺・画面比率を確認してから編集・歌詞同期へ進む。音声付き生成は元曲の該当区間と速度1倍で照合し、冒頭・中盤・末尾でリップシンクやダンスの拍がずれていないか確認する。

サービス名、モデル、ジョブID、費用の承認範囲、保存先、採用テイクをプロジェクトに記録する。APIキーや署名付きの一時URLは記録に含めない。

## 制作と同期

- 合意した構成に沿って素材制作・編集を進める。選んだ方法に応じて個別スキルを読む。
- 画像の全体表示／意図した寄りを構成に記録する。全体表示が求められた画像は、アスペクト比を保って収め、動きの途中も端が切れないようにする。
- 自動同期後は `mv-timing-edit` を使い、音声と映像を一緒に再生して、歌詞の入り・区切り・終わりとカットを確認・調整する。静止画や音声ストリームの存在確認で、同期確認を代用しない。
- 再生・聴取の手段がなければ、その制約と未確認箇所を明記し、音付きの確認用動画と調整方法を渡す。「同期確認済み」と記録しない。

## 確認ページと人による編集

シーン別の元曲付き確認ページとフル再生を残す。Remotion Studioは細かく編集したい人向けに併設し、確認だけの人にStudioを強制しない。どちらも同じ採用版を基準にし、保存と書き出しの反映状況を表示する。

確認ページに編集欄を設けるとき、またはStudio導入・移行・配布を行うときは [確認とStudioの併存手順](references/review-and-studio.md) を読む。元動画を保持した非破壊編集、標準機能の版確認、独立したカット/歌詞ノード、編集正本、手動変更の保護、実機での保存・再起動・書き出し検証を扱う。曲専用で検証した実装を汎用機能として導入済みとは扱わない。

確認ページの数値入力やJSONダウンロードだけでは「編集できる」と案内しない。修正案の提出だけなら「修正依頼用」と表示し、再生中の映像には反映されないことを入力欄の近くにも示す。直接編集を提供する場合は、変更の即時プレビュー、編集正本への保存、再起動後の保持、保存値を使った書き出しまでを接続して実機確認する。確認ページ自体にこの機能を実装してもよく、Studioを唯一の修正方法と説明しない。

独自スクリプトで初稿を作る場合も、手動修正をどの画面・保存先・書き出し経路で行えるかを制作記録に残す。動画の書き出し成功だけで予定した編集環境の引き渡しを完了としない。未実装ならその状態を初稿の案内時に明記し、依頼された編集環境の実装を残工程として扱う。

画像（静止画）MVの直接編集には、パック同梱の共通編集UIを使える。`remotion/` で `npm run editor -- --project <名前>`（見本は `--demo`、素材を直接指定するなら `--audio --lyrics --images`）。モーションと書体の一覧はカタログ・書体レジストリから自動生成され、追加スタイルも反映される。保存は `projects/<名前>/out/editor/editor-state.json`、書き出しは保存値から行う。使い方と確認済み範囲はパックの `docs/EDITOR_ja.md`。編集画面と MP4 書き出しは Windows 11 実機で確認済み（2026-10）。未確認の環境（macOS など）で使った場合は、起動・保存・再起動後の保持・書き出しを実機で確かめてから完成と伝える。動画素材・立ち絵ステージのプロジェクトも同じエディターで開ける（シーン・歌詞の見た目・カメラを後から直せる）。

## 完了の扱い

`mv-export` と `mv-qa` で技術チェックと見た目の確認を行う。報告は「構成合意済み」「自動同期済み・聴取未確認」「確認用初稿」「完成版」など、実際の状態に合わせる。自動QAの合格だけで、演出・同期も確認済みの完成版としない。

再開時はプロジェクトに保存した制作方針、構成、確認状況を読み、未完了の工程から進める。軽微な修正のたびに最初の選択へ戻さない。

## 引き継ぐ制作記録

プロジェクトの `production-review.md` を制作中に更新する。作り方と画面、構成表、素材制作の方法と採用結果、歌詞演出の方針、ユーザーの合意範囲、音付き確認の区間と調整結果、技術QA、未確認事項を記録する。状態は未着手・提案済み・合意済み・確認済み・未確認を実態に合わせて使う。確認していない項目を埋めて済ませない。記録は相談のたびに質問を増やすためでなく、既存回答の引き継ぎと再開に使う。

## エディターで後から直せるように作る（共通）
どの作り方でも、生成した見た目は既定値で、エディターでの行ごと・シーンごとの変更が必ず優先される作りにする（詳細は AGENTS.md「エディターで後から直せること」）。独自の描画やステージを足すときは `tests/editor_overrides.test.tsx` に追加して確認する。
キャラ・ゲスト・テロップなど歌詞以外の要素も、ステージ定義は既定値・エディターのパッチ（`data.stage`／`scenes[].stage`）が優先。描画に数値を直書きせず、定義データから読む。

## パック内での実行

このファイルは配布用コピー。編集原本は管理用ワークスペースの `.agents/skills/`。制作時は、この配布パックのルートにある `AGENTS.md` を読み、コマンドは `remotion/` で実行する。本文の `input/`、`projects/`、`docs/`、`gen/` はパックのルートを基準に解決する。
