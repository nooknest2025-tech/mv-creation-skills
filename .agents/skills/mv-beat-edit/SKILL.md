# mv-beat-edit

**モデルの目安: 標準モデル＋推論 medium**（迷ったら mv-direct で方針→ mv-run で実行）

## 仕組み
- カット長はプリセット×セクションで決まる（1小節 / 2拍 / 1拍 / 半拍 / 1/4拍、0 = 長回し）。サビは回を追うごとに細かく（エスカレーション）、エネルギーが高い所はさらに半分、静かな所は息継ぎで長く。
- カットは拍にスナップし、さらに `cutLead`（既定は約1〜3フレーム前）で前倒し → 人の目には「音ぴったり」に見える。
- プレサビの最後に半拍の黒ブレイク、冒頭はヒーローショット、終わりは最初の画に戻るループ（プリセットによる）。

## 判断と確認

既定で音の立ち上がりから可変間隔の拍候補を抽出し、十分な範囲を安定して追えた場合はカット・エディタのタイムラインと共通の文字演出に使う。結果は `out/beat-track.json` に保存し、既存の手動拍・BPMロックを優先する。候補が不安定ならBPMを使って未確認とする。`out/sync-audit.json` の冒頭・中盤・終盤の音の立ち上がりと拍グリッドとの差も確認候補として扱う。これは歌や伴奏の音も混じる簡易推定で、ビート確定ではない。BPMの倍・半分やテンポ変化を音付きで比較し、ユーザーのロックを保つ。

一部の立ち絵やモーショングラフィックスは引き続き一定BPMを使うため、全演出の可変テンポ対応は未完了。上は現在のプリセットの傾向で、全曲に適用すべき演出規則ではない。サビを必ず速くしたり、画を一律に前倒ししたりせず、歌声・音のアタック・演出意図を比べる。拍グリッドはBPM・位相・拍子が誤ることがあり、半分/倍のテンポや曲中のずれを `mv-intake-analysis` に従って確認する。前倒し量はプレビューと音付き再生で選び、固定値を感覚的な正解として断定しない。

## 調整
`npm run edit -- "サビは1/4拍で刻んで"` / `"Aメロは2小節ずつ"` / `"長回しで"` / `"画は0.1秒前から切り替え"` / `"BPMは128"` / `"拍を半拍ずらして"`
セクション別: `timing.perSection.chorus.cutLead`、ショット別: `timing.perShot`。視覚的には `npm run timing`。

## この環境でのパックの場所

作業ディレクトリまたは上位ディレクトリから、`AGENTS.md` と `remotion/package.json` を持つ制作パックのルートを確認する。管理用ワークスペースに `skill-pack-v3/MV_SKILL_PACK/` がある場合はそこを使う。PC固有の絶対パスを前提にしない。コマンドはパック内の `remotion/` で実行する。
