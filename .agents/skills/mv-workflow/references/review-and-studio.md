# シーン別確認とStudio編集の併存

確認ページに編集欄を設ける場合、ユーザーが編集環境を求めた場合、または生成MVを人へ引き継ぐ場合に読む。確認だけしたい人にStudioの操作を強制しない。以下は制作・実装の手順であり、このスキルを入れるだけで専用エディターが導入されるという意味ではない。

## 入口を2つ保つ

- **確認ページ**：カット別の元曲付き動画、全編再生、前/次、繰り返し、速度、修正前後/生成元の比較、参照画像、判断とメモ、メモの書き出し。Studio導入後も残す。
- **Studio**：カット・歌詞・音楽を独立編集する。利用するのは希望者。確認ページと同じ採用版を読み、Studio保存後の書き出しを確認ページにも反映する。書き出しが古い間は未反映と表示する。

どちらもショットIDと版を明示する。現在ブラウザーで開いている版と最新採用版が同じとは限らない。リンク切れでは配信プロセス・ポート・ファイルとHTTP応答を確認して復旧し、実際に再生できるリンクを渡す。サーバーが永続稼働するとは約束せず、移行先で使える起動手順を渡す。

## 確認ページで直接編集する場合

ページの役割を画面と案内で一致させる。

- **修正依頼用**：秒数やメモは依頼内容。JSONの保存は提案の持ち出しであり、編集正本の保存や動画更新ではない。焼き込み済みのMP4を再生しながら数値だけ変える欄には、その場で映像が変わらない旨を併記する。
- **直接編集用**：変更をプレビューへ即時反映し、編集正本へ保存し、その正本から修正版を書き出す。確認ページで完結してもよい。Studioは別の編集経路であり、既存ページを使えないと一律に説明しない。

直接編集では、焼き込み済み字幕の上に新字幕を重ねない。字幕なしの映像と元曲、独立した歌詞データからプレビューと書き出しを組み立てるなど、同じ編集値が両方へ反映される構成にする。カットや文字位置も編集対象なら、それらも共通の正本に含める。

「保存済み」「未保存」「書き出し未反映」「書き出し中」「書き出し失敗」を実態に合わせて表示する。保存先と現在の編集版・動画版を示し、書き出し失敗時に古いMP4を最新の成功結果として渡さない。ブラウザ内だけのメモ保存を、レンダラーが読むプロジェクト保存と混同しない。

実際の曲の検証用コピーで、提供する操作を端から確認する。

1. 歌詞の開始を0.5秒動かし、元曲付きプレビューで変更前後の表示位置を再生する。文字位置やカットの編集も提供するならそれぞれ変更する。
2. 保存後にページを再読込し、配信・保存プロセスも再起動して変更が残るか確認する。
3. 保存した正本から別版MP4を書き出し、同じ変更が実際に含まれることを確認する。変更なしの旧動画の存在確認で代用しない。
4. 変更前後の値、保存先、編集版と出力版、確認結果を制作記録に残す。検証用変更を採用版へ混ぜない。

画の切替調整を提供する場合は、ショットIDごとの切替時刻、素材選択、切替方法と長さを共通の正本に保存する。前後の区間が逆転する値や、区間より長いトランジションを検証し、境界の直前・途中・直後をプレビューと出力で確認する。

リリックモーションの選択を提供する場合は、まず既存のカタログと実装を確認する。利用可能なスタイルを根拠なく少数へ制限せず、見本と日本語名から選べるようにする。対応するスタイルと未対応の項目を区別し、見本だけ動いて本編出力には反映されない選択肢を完成機能として渡さない。対象の行・区間、スタイルとパラメーターを共通の正本へ保存し、プレビューと書き出しに同じ実装を使う。曲専用の簡略実装を既存カタログの完全対応と呼ばない。

未接続・未検証ならその範囲を明記し、直接編集機能の完成とはしない。スキル文書の改修と、既存プロジェクトのUI・保存・レンダラーの実装は別の作業として報告する。

## 元動画と非破壊の編集情報

生成元を変更せず保持し、カットは素材の使用範囲として記録する。生成元、採用テイク、編集用プロキシ、確認用の短いMP4、全編MP4を区別する。確認用の短い動画を唯一の編集素材にすると、Studioでバーを延ばしても元の余白を戻せない。

カットごとに、安定したID、相対素材パス、実測素材尺、素材fps、タイムラインの開始/長さ、素材側の開始/終了、速度または時間対応、クロップ・効果・採用版を記録する。タイムラインは30fpsなら整数フレーム。異なる素材fpsの開始位置は秒または有理数でも保持し、変換誤差を記録する。元音源の区間位置と生成添付音声のハッシュ/実測尺を別項目で保持する。

動画を速めても元動画そのものの長さは増えない。素材上限と隣接カットを越えて延ばせるとは説明しない。意図しない末尾静止・ループ・黒画面を確認する。過去の焼き込みクロップ/フレーム除去をプロキシから復元できるとは言わず、元動画へ戻す手順と履歴を渡す。

## Remotion標準機能を先に試す

1. 実際のpackage.jsonとインストール済みのRemotion/CLI/Studioの版、型定義、対応する公式仕様を確認する。`Track`、`Interactive`、ソース書き戻しは版によって異なる。未確認のAPIや別プロジェクト専用コマンドを、既存機能として案内しない。
2. 対応版では映像/歌詞/音楽のトラックと標準の波形・再生ヘッド・ズーム・スナップを使う。同一Trackの重複制限に注意し、クロスフェードは対応するトランジション構成または別トラックで実装する。
3. 全カット・全歌詞に独立したソースのJSXノードと安定した名前を付ける。現在時刻で親の配列をfilterして要素自体を消す構成は避け、Sequence等の時間指定で表示する。
4. **mapで並べただけでは独立編集にならない場合がある。** 小さい配列の例で個別選択・変更・保存・再起動を実機確認する。同じソースノードが複数インスタンス扱いになる場合は、各項目を独立ノードへ展開する。
5. 歌詞の位置/サイズ/回転/透明度/フォント/色/縁取り/影と、移動/拡大/フェードのキーを編集可能なpropsにする。対応版のInteractiveとインラインのinterpolateを使い、イージングも編集可能にする。既存スタイルの複雑な内部計算が自動でGUI化されるとは説明しない。
6. 実制作でRemotion 4.0.538の標準編集は`--rspack`付き起動で動作を確認した。通常起動で描画だけでき、選択やソース解析が有効にならない場合は、対応版の起動方式を確認する。全バージョンに同じオプションを無条件適用しない。
7. 全要素を一覧に残しながら、歌詞を初期状態で非表示にするなら、編集可能な親Opacity等を利用し表示手順を案内する。トラックを非マウントにして編集対象まで消さない。

標準機能でできない部分だけ最小限のUIを追加する。既存のFFmpeg/MCP、通常MV、リリック、自動解析の経路は置き換えない。

## 編集正本と自動制作

正本を1つ定める。Studioがソースへ直接保存する構成では、そのプロジェクトのTSXを正本にできる。JSONを正本とする場合はGUIの保存先まで実装・検証する。TSXとJSONの両方を独立した正本として更新しない。

- 初回取り込みは採用版を読み、以後は正本があれば自動再生成で上書きしない。
- Codexは現行の正本を読んで名前付きの対象だけを変更する。想定した旧値と違う場合は競合として扱い、手動のキーや位置を初期化しない。
- 変更前のスナップショットを取り、書き出し時にも正本の版/ハッシュを保存する。再取り込みは別版または明示的な差分マージ。
- 取り込み履歴や採用素材一覧は監査データとして残す。正本と混同しない。
- 映像は原則ミュート、音楽は独立トラック。Studioで変えた音楽の位置/音量を、最終muxで無条件に元曲へ戻さない。元音源自体は不変。

## 完了に必要な実機テスト

今回扱う実際のMVで、カットの3フレーム移動、歌詞のマウス移動、縁取り変更、キーの移動、保存、Studioプロセスの再起動、変更保持、修正入りMP4出力を確認する。変更テストで承認済みの制作内容を変えた場合は、検証版を別版に残して本番の採用状態と混同しない。

映像/音声の全編デコード、fps/尺、元音源ハッシュと出力の音声有無も確認する。WAV→AACと、最終muxの音声パケットコピーを区別する。ツール同梱FFmpegはmd5 muxer等の機能を省いている場合があるので、実バイナリーの対応を確認する。`-shortest`でAAC末尾パケットが落ちる場合、完全なパケット一致と誤記しない。

実装しただけ、型チェックだけ、スクリーンショットだけでは操作検証完了としない。検証できなかった操作や外部MCP本体への未接続は、成功したローカルFFmpeg処理と分けて記録する。

## 配布

一般的な手順・相対パスのテンプレート・実際にテストした補助コードを配布する。曲専用の編集TSX、音源、歌詞、人物画像、生成動画、ユーザーメモ、モデルキャッシュ、認証情報、ジョブID/署名URLは含めない。ローカルで検証した曲専用のコードを、汎用配布コードとして検証済みとはしない。スキルの変更と実行環境の変更範囲をそれぞれ明記する。
